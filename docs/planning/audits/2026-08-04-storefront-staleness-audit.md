## Environment note (not a product bug, but affects future scripted-auth work)

Local `npm run dev` boots with `NEXTAUTH_URL=http://localhost:3000` from `.env`, while this
task's dev server was required to bind port 3001. With that mismatch, or even with
`NEXTAUTH_URL` corrected to port 3001 but `AUTH_TRUST_HOST` unset, the credentials sign-in POST
fails server-side with `MissingCSRF: CSRF token was missing during an action callback`
(confirmed via server logs) and the login form silently stays on `/login` with no visible
network‑level explanation to the user. Setting `AUTH_TRUST_HOST=true` (in addition to matching
`NEXTAUTH_URL` to the actual port) fixed it for this session's screenshot run. No `.env` file
was modified — the fix was applied as a shell-only override for verification. Anyone scripting
authenticated flows against a non-default port locally will hit the same wall; worth a BACKLOG
note since CLAUDE.md currently only documents `AUTH_TRUST_HOST` as a CI/E2E requirement, not a
local one.
